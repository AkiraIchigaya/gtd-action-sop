# GTD Action SOP

**一个面向个人任务管理的 AI Agent Skill**

> 把脑海中的零散想法转化为下一步行动，让任务管理不再成为另一项需要管理的任务。

**当前版本：v1.2**

## 📖 项目简介

GTD Action SOP 是一个基于 GTD（Getting Things Done）理念设计的跨平台 AI Agent 工作流 Skill。

它通过四个核心阶段和五个可选方法，帮助使用者整理收集箱、明确任务目标、制定下一步行动、管理截止事项，并持续复盘和维护任务系统。

本项目的目标不是让 AI 替你决定人生，而是将重复、机械的任务整理工作交给 AI，保留使用者对目标和重要选择的控制权。

**主要特点**

- 四阶段任务管理闭环
- 自动将模糊任务转化为可执行指令
- 支持多步骤项目与委托等待事项
- 五种可按需启用的效率方法
- 使用标准 Markdown 保存任务状态
- 兼容 Obsidian 和普通文本笔记
- 修改本地文件前必须取得用户确认
- 无文件访问权限时也可通过对话使用

## 🔄 四大核心流程

| 阶段 | 主要任务 |
|---|---|
| ① 收集 | 快速记录所有闪念，不急着整理 |
| ② 决策 | 明确目标，把事项转化为具体行动 |
| ③ 行动 | 根据剩余时间、精力与环境选择行动 |
| ④ 校准 | 更新任务状态、复盘并保持系统运转 |

**基本流程**

收集 → 决策 → 行动 → 校准 → 下一轮收集

其中，决策阶段使用四关流程：

1. 这件事要不要做？
2. 想达到什么目标？
3. 需要执行哪些具体行动？
4. 能否在两分钟内完成？

## 🧩 五大可选方法

核心四阶段默认生效，以下方法按需启用。

| 方法 | 适用情况 |
|---|---|
| 指令打包法 | 批量处理同类任务，集中跟进委托事项 |
| 刚性截止法 | 区分真正的截止日期与个人期望日期 |
| 时间块 | 制定保留休息和空白时间的日程 |
| 游戏小人法 | 改善任务启动困难与无意识分心 |
| 趋势打卡术 | 关注长期进步，而不是单日打卡是否中断 |

无需一次启用全部方法。

## 🚀 快速开始

### 1. 获取 Skill

下载本仓库，保留以下结构：

```text
gtd-action-sop/
├── SKILL.md
├── README.md
├── CHANGELOG.md
└── references/
    ├── decision-flow.md
    ├── examples.md
    ├── plugins.md
    ├── sop-table.md
    └── trigger-list.md
```

### 2. 加载 Skill

在支持自定义 Agent Skill 的环境中，根据平台要求加载 `SKILL.md` 和 `references/` 目录。

如果平台不支持原生 Skill 加载，可以将这些文件作为项目资料提供给 AI，并要求它遵循其中的工作流。

注意：不同 AI 平台对文件读取、持久化状态及自动执行的支持程度不同，文件上传不代表已完成原生安装。

### 3. 启动首次使用流程

向 AI 发送：

> 请加载 gtd-action-sop v1.2。先向我介绍四个核心阶段和五个可选方法，然后引导我建立第一个 GTD 看板。任何文件写入操作都必须先获得我的确认。

按照提示完成初始收集箱和任务看板的建立。

### 4. 日常使用

**捕获闪念**

> 先帮我记到收集箱，不用整理。

**清空收集箱**

> 帮我按照四关决策流程整理这些事项。

**选择下一步**

> 我现在有 30 分钟，精力一般，在宿舍。推荐我做什么？

**每日安排**

> 根据我的任务清单和刚性截止事项，安排今天的时间块，保留休息时间。

**每日复盘**

> 帮我复盘今天完成的任务，检查哪些项目需要补充下一步行动。

**中断后恢复**

> 我已经几天没有维护 GTD 系统了，请从校准与复盘开始，帮我恢复任务状态。

## 📱 跨设备使用

本 Skill 使用标准 Markdown 格式，可配合 Obsidian 或其他支持 Markdown 的笔记软件使用。

推荐采用以下分工：

- **AI Agent：** 负责整理、决策辅助、行动推荐与复盘。
- **Markdown 文件：** 负责保存长期任务状态。
- **Obsidian：** 负责查看、编辑和管理任务看板。
- **同步工具：** 根据个人需求实现跨设备文件同步。

Skill 本身不提供文件同步服务，也不会自动保证跨会话记忆一致。

没有文件访问权限时，AI 可以输出完整 Markdown 内容，由用户自行保存。

## 🔒 数据安全原则

1. AI 不得擅自编造截止日期、任务状态或用户意图。
2. 涉及重要目标与价值判断时，必须保留用户的决定权。
3. 修改、覆盖、删除本地文件之前，必须展示拟修改内容并取得明确确认。
4. 未经授权，不得修改用户的 Obsidian Vault。
5. 不得将 Skill 内置参考文件当作个人任务看板覆盖。
6. 建议定期备份任务文件，尤其是启用跨设备同步时。
