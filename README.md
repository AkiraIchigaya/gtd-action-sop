# GTD Action SOP

**一个面向个人任务管理的 AI Agent Skill**

> 把脑海中的零散想法转化为下一步行动，让任务管理不再成为另一项需要管理的任务。

**当前版本：v1.3**

## 📖 项目简介

GTD Action SOP 是一个基于 GTD（Getting Things Done）理念设计的跨平台 AI Agent 工作流 Skill。

它通过四个核心阶段和五个可选方法，帮助使用者整理收集箱、明确任务目标、制定下一步行动、管理截止事项，并持续复盘和维护任务系统。

本项目的目标不是让 AI 替你决定人生，而是将重复、机械的任务整理工作交给 AI，保留使用者对目标和重要选择的控制权。

**主要特点**

- 四阶段任务管理闭环
- 自动将模糊任务转化为可执行指令
- 支持多步骤项目与委托等待事项
- 五种可按需启用的效率方法
- 使用标准 Markdown 保存任务状态
- 兼容 Obsidian 和普通文本笔记
- 修改本地文件前必须取得用户确认
- 无文件访问权限时也可通过对话使用

## 🔄 四大核心流程

| 阶段 | 主要任务 |
|---|---|
| ① 收集 | 快速记录所有闪念，不急着整理 |
| ② 决策 | 明确目标，把事项转化为具体行动 |
| ③ 行动 | 根据剩余时间、精力与环境选择行动 |
| ④ 校准 | 更新任务状态、复盘并保持系统运转 |

**基本流程**

收集 → 决策 → 行动 → 校准 → 下一轮收集

其中，决策阶段使用四关流程：

1. 这件事要不要做？
2. 想达到什么目标？
3. 需要执行哪些具体行动？
4. 能否在两分钟内完成？

## 🧩 五大可选方法

核心四阶段默认生效，以下方法按需启用。

| 方法 | 适用情况 |
|---|---|
| 指令打包法 | 批量处理同类任务，集中跟进委托事项 |
| 刚性截止法 | 区分真正的截止日期与个人期望日期 |
| 时间块 | 制定保留休息和空白时间的日程 |
| 游戏小人法 | 改善任务启动困难与无意识分心 |
| 趋势打卡术 | 关注长期进步，而不是单日打卡是否中断 |

无需一次启用全部方法。

## 🚀 快速开始

### 1. 获取 Skill

下载本仓库，保留以下结构：

```text
gtd-action-sop/
├── SKILL.md
├── README.md
├── CHANGELOG.md
└── references/
    ├── board.md
    ├── decision-flow.md
    ├── examples.md
    ├── glossary.md
    ├── plugins.md
    ├── sop-table.md
    └── trigger-list.md
```

### 2. 加载 Skill

在支持自定义 Agent Skill 的环境中，根据平台要求加载 `SKILL.md` 和 `references/` 目录。

如果平台不支持原生 Skill 加载，可以将这些文件作为项目资料提供给 AI，并要求它遵循其中的工作流。

注意：不同 AI 平台对文件读取、持久化状态及自动执行的支持程度不同，文件上传不代表已完成原生安装。

### 3. 启动首次使用流程

向 AI 发送：

> 请加载 gtd-action-sop v1.2。先向我介绍四个核心阶段和五个可选方法，然后引导我建立第一个 GTD 看板。任何文件写入操作都必须先获得我的确认。

按照提示完成初始收集箱和任务看板的建立。

### 4. 日常使用

**捕获闪念**

> 先帮我记到收集箱，不用整理。

**清空收集箱**

> 帮我按照四关决策流程整理这些事项。

**选择下一步**

> 我现在有 30 分钟，精力一般，在宿舍。推荐我做什么？

**每日安排**

> 根据我的任务清单和刚性截止事项，安排今天的时间块，保留休息时间。

**每日复盘**

> 帮我复盘今天完成的任务，检查哪些项目需要补充下一步行动。

**中断后恢复**

> 我已经几天没有维护 GTD 系统了，请从校准与复盘开始，帮我恢复任务状态。

## 📱 跨设备使用

本 Skill 使用标准 Markdown 格式，可配合 Obsidian 或其他支持 Markdown 的笔记软件使用。

推荐采用以下分工：

- **AI Agent：** 负责整理、决策辅助、行动推荐与复盘。
- **Markdown 文件：** 负责保存长期任务状态。
- **Obsidian：** 负责查看、编辑和管理任务看板。
- **同步工具：** 根据个人需求实现跨设备文件同步。

Skill 本身不提供文件同步服务，也不会自动保证跨会话记忆一致。

没有文件访问权限时，AI 可以输出完整 Markdown 内容，由用户自行保存。

## 🔒 数据安全原则

1. AI 不得擅自编造截止日期、任务状态或用户意图。
2. 涉及重要目标与价值判断时，必须保留用户的决定权。
3. 修改、覆盖、删除本地文件之前，必须展示拟修改内容并取得明确确认。
4. 未经授权，不得修改用户的 Obsidian Vault。
5. 不得将 Skill 内置参考文件当作个人任务看板覆盖。
6. 建议定期备份任务文件，尤其是启用跨设备同步时。

# 使用指南与闪念收集方法

## 🚀 一、如何使用 GTD Action SOP

### 1. 准备工作

使用本 Skill 不要求用户拥有编程知识，也不要求安装 Obsidian。

推荐准备：

- 一个可以读取 Skill 文件的 AI 助手
- 一个用于保存闪念的收集箱
- 一个长期保存任务状态的 Markdown 文件

推荐组合：

| 工具 | 主要用途 |
|---|---|
| ChatGPT | 闪念收集、任务整理、行动建议 |
| Obsidian | 保存 GTD 看板与历史记录 |
| GitHub | 获取、维护和分享 Skill |
| 其他 AI Agent | 在支持的环境中运行相同工作流 |

以上只是推荐组合，实际使用时可以自由替换。

### 2. 首次启动

下载仓库并将 `SKILL.md`、`references/` 中的参考文件提供给 AI。

如果使用 ChatGPT Projects，可以：

1. 创建一个名为「GTD 行动管理」的项目。
2. 将 Skill 文件添加到项目资料中。
3. 在项目指令中要求 AI 遵守 Skill 的操作规则。
4. 创建新的对话，启动首次使用流程。

首次使用提示词：

> 请阅读项目资料中的 gtd-action-sop v1.2。
>
> 先检查核心规则与 references 参考文件是否完整，再向我介绍四阶段工作流。
>
> 引导我建立第一个 GTD 看板。
>
> 所有文件修改必须先展示变更内容并征得我的确认。不要自行推测截止日期或个人目标。

完成后，建议保存一份 `gtd-board.md`，作为长期任务状态的主要来源。

### 3. 日常运行流程

#### 早晨：安排

将当前 GTD 看板提供给 AI，发送：

> 请按照 GTD Action SOP 进行今日安排。
>
> 先检查愿望箱，再清空收集箱。
>
> 结合现有行动清单、项目清单和刚性截止事项，帮助我确定今天的行动方向。
>
> 不确定的信息请询问我，不要自行编造。

#### 白天：执行

当不知道下一步做什么时：

> 我现在有 40 分钟，精力一般，正在宿舍。
>
> 请根据已经决策的任务清单，推荐唯一一条最适合现在执行的指令。

AI 应根据时间、精力和环境推荐行动，而不是要求用户重新规划所有事项。

#### 晚上：校准

> 请进行今天的 GTD 复盘。
>
> 根据我提供的完成情况更新任务状态，检查每个未完成项目是否保留了下一步行动。
>
> 先给出修改预览，确认后再更新看板。

不必每天完成所有任务，重要的是使清单持续反映真实状态。

### 4. 中断数天后如何恢复？

如果一段时间没有使用系统，不需要删除旧看板重新开始。

发送：

> 我已经几天没有维护 GTD 系统了。
>
> 请启动系统重启流程，先核对旧任务状态，检查等待事项与项目下一步，再处理新增收集箱。
>
> 不要直接为我重新安排所有任务。

系统将从「校准」开始恢复，而不是强迫用户补完中断期间的所有记录。

## 💡 二、闪念收集方法

### 1. 什么是闪念？

闪念是任何突然出现在脑海中、可能值得以后重新查看的信息。

例如：

- 「下周的实验报告还没写。」
- 「好像要买新的笔记本。」
- 「突然想到一个数学问题。」
- 「以后想学习摄影。」
- 「有人还没回复我的消息。」
- 「想到一个不错的项目创意。」

这些内容不一定都是任务。

**收集阶段只负责记住它们，不负责判断它们。**

### 2. 五秒收集原则

当闪念出现时：

**想到 → 记录 → 返回原来的事情**

不需要：

- 立即确定完成日期
- 判断任务的重要程度
- 拆解执行步骤
- 给事项分类
- 把内容改写成标准任务指令

例如，脑海中出现：

> 感觉数学笔记的目录太乱了。

只需要原样记录：

```markdown
- [ ] 感觉数学笔记的目录太乱了
```

不必立即整理笔记。

之后在决策阶段，AI 才会协助明确目标，并将其转换成可执行行动。

### 3. 推荐方案：独立闪念对话

对于经常使用 ChatGPT 的用户，可以创建两个对话。

**对话 A：闪念收集箱**

用途：只接收新想法，不做任务决策。

首次发送：

> 这个对话只用于收集闪念。
>
> 我会随时发送想法、任务、灵感、担忧和提醒。
>
> 请保留原意，不主动分类、不拆解任务、不安排时间。
>
> 每次只简短确认收到的内容。
>
> 当我说「导出收集箱」时，把当前对话中可见的闪念按原始顺序整理成 Markdown。
>
> 不要声称内容已经保存到外部文件，除非实际完成了文件写入。

之后就可以直接发送：

> 想研究一下新的数学学习方法。

> 周五可能有作业要交。

> Obsidian 的笔记目录需要重新规划。

无需使用复杂指令。

**对话 B：GTD 决策与管理**

用途：运行完整 GTD Skill。

当准备整理闪念时：

1. 在对话 A 中导出收集箱。
2. 将结果复制到对话 B。
3. 同时提供最新的 GTD 看板。
4. 让 AI 按四关决策流程处理。
5. 检查 AI 的修改建议。
6. 确认后将更新结果保存回看板。

推荐提示词：

> 下面是尚未决策的闪念。
>
> 请按照 gtd-action-sop v1.2 的四关决策流程，从头到尾依次处理。
>
> 涉及重大目标取舍或信息不明确的事项，请先向我确认。
>
> 最后输出需要更新的任务区块，不要擅自修改原始数据。

**注意：** 不同 ChatGPT 对话之间不应被视为可靠的自动同步数据库。即使处于同一个 Project，也建议显式导出和传递收集箱内容。

### 4. 使用 Obsidian 收集闪念

如果希望数据长期保存，可以在 Obsidian 中创建：

`inbox.md`

内容示例：

```markdown
# 闪念收集箱

- [ ] 想重新整理数学笔记目录
- [ ] 周五可能有作业
- [ ] 研究新的时间管理方法
- [ ] 以后尝试学习摄影
```

日常使用时，只需在文件末尾添加一条新记录。

等到安排阶段，再统一交给 AI 进行决策。

对于跨设备用户，可以通过可信的同步方案在手机和电脑之间同步这个 Markdown 文件。

注意避免多个设备同时编辑同一文件造成冲突，建议保留版本历史或定期备份。

### 5. 手机端如何收集？

推荐按照使用环境选择：

| 使用场景 | 推荐方式 |
|---|---|
| 正在使用 ChatGPT | 直接发送到闪念收集对话 |
| 不方便打字 | 语音输入一句话 |
| 没有网络 | 手机本地笔记或 Obsidian |
| 发现有用网页 | 复制链接并附一句说明 |
| 正在电脑前 | 直接写入 `inbox.md` |
| 无法使用电子设备 | 先记录在纸上，之后转入收集箱 |

可以同时存在多个收集入口，但建议尽量不超过五个，并在整理时检查全部入口。

### 6. 什么时候整理闪念？

建议每天安排一个固定时间集中处理收集箱。

不要求每次一口气处理完所有内容。

整理时，AI 依次检查：

**第一关：做还是不做？**

将事项分流至垃圾桶、收纳箱、愿望箱，或继续处理。

**第二关：目标是什么？**

明确希望最终实现的结果。

**第三关：需要哪些行动？**

将模糊想法改写为可以执行的具体指令。

**第四关：两分钟内能完成吗？**

能立即完成的，标记为立刻做；不能的，根据行动数量进入动作清单或项目清单。

完成决策后，收集箱中的事项才正式进入任务管理系统。

### 7. 什么时候不应该只收集？

如果事项属于必须立即处理的紧急情况，应先采取必要行动，而不是等待下一次收集箱整理。

如果用户只是在表达情绪、寻求交流或讨论方法论，也不应未经同意就将内容变成任务。

### 8. 如何防止收集箱越来越大？

遵守三个简单原则：

1. 捕获闪念时不要整理，降低记录成本。
2. 安排阶段按照原始顺序逐条决策，避免只处理简单事项。
3. 定期检查遗漏入口，避免多个收集箱长期积压。

**收集箱不是任务清单，而是尚未决策的信息入口。**

## 🔐 三、数据保存与隐私建议

GTD Action SOP 提供工作流规则，不自动提供跨设备同步或可靠的长期存储。

推荐将 Markdown 文件视为任务状态的正式记录。

在不同对话、不同 AI 平台之间切换时，应主动提供最新看板。

修改文件前必须先查看变更摘要，并获得用户确认。

对包含个人隐私的收集箱，建议使用受信任的私有存储空间，不要直接提交到公开 GitHub 仓库。

**核心原则：**

> 收集时不决策，决策时不遗漏，行动时不重新规划，复盘时保持系统与现实一致。

*Capture freely. Decide deliberately. Act clearly. Review consistently.*

*Capture ideas. Clarify actions. Keep moving.*
